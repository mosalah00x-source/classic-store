# Contract Gaps & Specification Mismatches

This document logs all identified mismatches, missing endpoints, and contract gaps between the static UI prototype, the OpenAPI specification, and the Spring Boot backend implementation.

| ID | Description | Evidence | Impact on Frontend | Suggested Owner |
| :--- | :--- | :--- | :--- | :--- |
| **GAP-01** | **CORS unconfigured on backend** | `backend/src/main/java/com/classicstore/common/config/SecurityConfig.java` (no `.cors()` configuration) | Cross-origin API calls directly from browser (`http://localhost:3000`) will be blocked by CORS policy. Frontend must proxy requests or backend must enable CORS. | Backend |
| **GAP-02** | **Missing Address mutation endpoints** | `AddressController.java` only implements `GET`, `POST`, `GET /{id}`. Missing `PUT /{id}`, `DELETE /{id}`, `PATCH /{id}/default` (which are declared in `openapi.yaml`). | Users cannot edit, delete, or change default address via API. | Backend |
| **GAP-03** | **Missing Categories Tree API** | Prototype requires header mega menu categories. No `GET /categories` or `GET /categories/tree` endpoint exists in `openapi.yaml` or backend (only `GET /products?categoryId=...`). | Frontend mega menu and category filters cannot fetch category list dynamically from API. Must be mocked or added to spec/backend. | Product / Backend |
| **GAP-04** | **Missing Governorates & Cities Reference API** | Checkout & address forms require governorate and city dropdowns (`governorateId`, `cityId`). No `GET /governorates` or `GET /governorates/{id}/cities` exists in `openapi.yaml` or backend. | Address forms cannot populate Egyptian governorates/cities from API. Must be mocked or added to spec/backend. | Product / Backend |
| **GAP-05** | **Missing Wishlist / Favorites API** | Prototype UI includes wishlist functionality (heart icon toggle). No wishlist endpoints exist in `openapi.yaml` or backend. | Wishlist functionality must remain client-side (`localStorage`) until backend adds wishlist endpoints. | Product |
| **GAP-06** | **Flyway Migrations Disabled in Application YML** | `backend/src/main/resources/application.yml` line 17 (`spring.flyway.enabled: false`). | Local or staging backend deployment will not auto-apply database migrations unless explicitly enabled or run via CLI. | Backend |
| **GAP-07** | **SPEC-ONLY Business Domains** | Catalog, Cart, Checkout, Orders, Payments, Returns, and Admin domains have NO Java controllers/services implemented (only `package-info.java` exists). | Frontend tasks T11-T13, T15-T18, T20-T25 cannot connect to real backend; must rely on MSW / mock server. | Backend |
| **GAP-08** | **Address DTO Field Name Alias (`line1` vs `street`)** | `AddressInput.java` accepts `line1` and maps it to `street`, and `AddressResponse.java` returns both `line1` and `street`. `openapi.yaml` only declares `street`. | Frontend should use `street` field consistently as declared in OpenAPI. | Backend / Frontend |
| **GAP-09** | **Missing Reservation Countdown Expiry in Cart/Order Schemas** | DB schema has `inventory_reservations.expires_at`, but OpenAPI `CartResponse` and `OrderResponse` do not expose reservation expiration time to end user. | Frontend cannot display real-time reservation countdown timers on checkout/cart without backend schema update. | Product / Backend |
| **GAP-10** | **Rate Limiting Not Implemented** | `AuthService.java` line 119 has `// TODO: Rate limiting on login endpoint`. | Login and registration endpoints are vulnerable to brute-force attacks if not rate limited at gateway / proxy level. | Backend / DevOps |
